Imputation lives inside the cross-validation pipeline
The zero → NaN rule is deterministic and learns nothing, so it is leak-free outside the pipeline. The imputer learns medians, so it is a step of the scikit-learn Pipeline: Pipeline([("impute", SimpleImputer("median")), ("model", RandomForest)]) — refitted on every training fold, so a validation fold never influences how it is filled.

Generative layer 1 — synthetic patients
Deep generative models (CTGAN, a GAN for tables; TVAE, a variational autoencoder) and a statistical Gaussian Copula learn the distribution of diabetic patients and sample new ones to rebalance training — benchmarked against SMOTE and no augmentation.
Generative layer 2 — LLM explanations
A large language model turns the prediction, exact SHAP values and clinical reference bands into a plain-language summary for the patient, with a clinician-review disclaimer appended by the server on every response.

Re-validation protocol for India

What we would do before any Indian deployment
    Asian-Indian BMI cut-offs
    Indians develop type-2 diabetes at a lower BMI. The predictor's BMI chip uses the WHO / ICMR action points (overweight ≥ 23, obese ≥ 25) rather than the global 25 / 30.

    Limits we refuse to paper over

    Stated in models/model_card.json, shipped beside the weights
    • Population. Every patient is female, of Pima heritage, aged 21+. Anything else is extrapolation.
    • Sample size. The test set holds — positive cases — hence the bootstrap intervals.
    • Synthetic data. No generator beat class weighting, so the deployed model trains on real patients only.
    • LLM risk. The language model can be fluent and wrong; it sees only computed numbers, cannot diagnose, and a clinician must review.
    • Automation bias. The UI shows a probability, a band and an action — never a bare “negative”.
    • Not a diagnosis. The output ranks patients for a confirmatory blood test. It never replaces one.
